# Project plan: kinfolk

## Brief

**Type:** Website design

**Problem:** A neighborhood restaurant website should answer practical questions while conveying its atmosphere.

**Audience:** A diner choosing a meal and considering a table.

## Experience flow

1. Arrive at a direct, descriptive introduction.
2. Review the sample interface and its scope before interacting.
3. Try the core control: Browse menu categories and try a non-submitting reservation flow.
4. See a local result or demonstration state without sending a request to a service.

## Interaction

Menu filters switch categories; the reservation action returns a demo confirmation without sending a booking.

## Key design decision

Put location, service hours and menu discovery near the top, then use a warm editorial layout.

## Boundaries

Restaurant, menu, address and hours are fictional sample content.

All named businesses, people, products, schedules, prices and quantitative values are fictional portfolio content. Replace them only with verified, permissioned material.

## Next iteration

Add verified menu/allergen details and connect a real reservation provider with consent.

## Learning goals

- Structure a complete page with meaningful headings, landmarks and labelled controls.
- Separate visual rules in CSS from interaction logic in JavaScript.
- Make states understandable with keyboard controls and live status text.
- Document assumptions and the boundary between a helpful prototype and a production service.
